Se añadieron `--compression none` a los fixtures porque `rpk` usa Snappy por defecto y el build local de `librdkafka` no incluye ese codec. Aumentar la ventana inicial del consumidor corrige un race con el arranque lento local, pero el E2E completo aún requiere el runner Linux de CI.

El build del perfil `app` inició, pero BuildKit reportó `Read-only file system` e `Input/output error` al instalar certificados dentro de la etapa Debian y se quedó sin progreso; se interrumpió. No se validaron PostgreSQL API migrations, endpoints, ingestión del perfil `app`, ni se pudo restaurar el stack normal porque Docker Engine se desconectó nuevamente. Los volúmenes de `taq-e2e` eran descartables; los volúmenes del proyecto normal no se borraron y quedaron pausados.

El actualizador de Graphify tampoco pudo ejecutarse en Windows: `graphify update .` termina con `uv trampoline failed to canonicalize script path`. El grafo queda pendiente de actualización. Compose config fue revalidado después de los cambios y pasó; `git diff --check` no encontró errores de whitespace (solo avisos CRLF de Git).

## Decisión de release

**NO-GO para piloto externo o servicio público.** La suite unitaria local pasa, pero faltan E2E con infraestructura, validación de migraciones, revisión de privacidad/legal/licencias, secret manager, TLS/cifrado, retención y borrado propagado, firma/procedencia de artefactos, restore y despliegue operable.

Además, taq-api comparte un único cliente PostgreSQL mediante mutex; esto serializa las operaciones de la base y requiere un pool de conexiones antes de afirmar capacidad multi-tenant o throughput público.
